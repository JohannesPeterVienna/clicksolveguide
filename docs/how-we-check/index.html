How we check our guides

A troubleshooting guide is only useful if its menu paths exist on your screen and its steps don't make things worse. This page explains how ClickSolve Guide is put together, which sources each page is based on, and where the limits are.

Reviewed November 2, 2026Applies to: every diagnosis and guide on this site

The layer model

Every diagnosis on this site uses the same idea: a request from your screen passes through layers, and a fault sits in one of them. For internet problems the layers are your device, the Wi-Fi link, the router, your internet provider (ISP) and the service – the website or app at the other end. Printer problems use a shorter chain: computer and print queue, connection, router, printer.

A good check rules out a whole layer without changing anything. “Does another device on the same Wi-Fi work?” clears router and provider in one go. “Does the site open on mobile data?” clears the website. We order the checks so that the cheapest, safest and most informative ones come first, and we only show fixes once the layer is narrowed down.

How a decision tree is written

Each diagnosis is stored as a small data file: questions, possible answers, which layers each answer rules out or makes suspicious, and the result each path leads to. Before the site is published, an automated test walks through every possible path of every tree. It fails the build if a path ends nowhere, loops, refers to a missing step, or offers a step that changes a setting without saying how to undo it. The same code that runs the tree in your browser is used in that test.

The trees are deliberately short. If a question doesn't change the outcome, it is removed. If two answers lead to the same steps, they are merged.

Menu paths and versions

Menus differ between Windows 11 and Windows 10, and macOS renamed System Preferences to System Settings in macOS 13 Ventura. Every menu path on this site is written separately for each version it applies to, and the version switcher shows the one you choose. Android is harder: phone makers rename menus, so Android paths name the stock Android wording and, where it differs, Samsung's. When we are not sure a path is identical on every build, we write it more generally (“Settings > Network & internet”) rather than inventing a precise-looking path.

Which sources each page is based on

Steps and menu paths follow the official documentation of the company that makes the product: Microsoft Support and Microsoft Learn for Windows and its commands, Apple Support and the macOS, iPhone and iPad user guides, Google's Chrome and Android help, and the printer makers' own support sites. Security advice follows consumer-protection agencies such as the U.S. Federal Trade Commission. Each page lists its sources at the bottom and shows the date it was last reviewed.

We do not claim lab testing on hardware we don't have. The source line at the top of each page names the documentation a page is based on – it does not mean someone reproduced every fault on every device. Menus can change with updates; tell us when one differs.

What we leave out on purpose

  • No phone numbers – ours or anyone else's. Support numbers belong on your contract, receipt or the maker's official site.
  • No “optimizer”, “cleaner”, “driver updater” or remote-access tools. Drivers come from Windows Update, macOS updates or the device maker.
  • No instructions for getting past certificate or security warnings. A diagnosis that reaches one stops and lists only safe actions.
  • No registry edits for everyday problems.

Limits

A decision tree can only follow the answers it gets. If a check is misread – a router light that looks normal but isn't – the result can point to the wrong layer. That's why every result says why it was reached, and why “Back one step” is always available. Company-managed computers may have menus locked or changed by IT; in that case your IT department is the right first contact. For hardware faults, the device maker's support is the place to go.

Corrections and review

When an operating system update changes a menu, or a reader reports a path that doesn't match, the page is corrected and its review date changes. You can report errors through the contact page. Pages are reviewed again after major Windows, macOS, iOS and Android releases.
