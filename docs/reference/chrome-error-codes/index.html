Chrome network error codes (ERR_…)

The small grey code on a Chrome error page – ERR_NAME_NOT_RESOLVED, ERR_CONNECTION_RESET – is the most precise thing the browser tells you. This page explains the 29 codes that say something about where the fault sits, and the 8 results of Chrome’s own DNS test, each with the layer it points to and the check that comes next. The lookup recognises all 249 names in Chromium’s list.

How to read a Chrome code

Chromium, the open-source project behind Chrome, Edge, Brave, Opera and Vivaldi, keeps its network errors in one numbered list. The name on the error page is the list’s name with “ERR_” in front; the number appears on some pages and in logs. The list is sorted into numbered ranges, and the range already says a lot:

9 rows
Ranges of Chromium’s network error list
RangeNumbers in useCodesWhat a code from this range tells you
System-1 to -3734A general or local error – files, memory, permissions or a cancelled request. On its own it does not point to the router, the provider or the website.
Connection-100 to -19073The connection to the server or to a proxy failed at network or encryption level. Compare with another website and with mobile data to see whether it follows the website or your network.
Certificate-200 to -22017A certificate error: the browser could not confirm that the site is the one it claims to be. Do not click through and do not type passwords or card numbers. Check the date and time on your device, then try the site later or from another network; if the warning stays, only the website’s owner can fix it.
HTTP-300 to -38863A problem in the HTTP exchange with the server – the connection itself worked. Most of these can only be fixed by the website; a private window shows whether your browser data plays a part.
Cache-400 to -41415Concerns Chrome’s local cache of earlier downloads, not the network.
Unnamed range-501 to -5088Chromium’s list gives this range no name.
Certificate manager-701 to -71614Concerns importing or managing certificates in the browser, not loading a normal web page.
DNS resolver-800 to -82118The name lookup failed. The website was never contacted; the fault is on the way to the DNS server or at the DNS server.
Blob-900 to -9067Concerns data the page handles inside the browser, not the network.

Most of the 249 codes never reach an error page; they are used inside the browser. For a code that is not explained below, the lookup gives its number and range and links to Chromium’s source file, where each code carries a short comment for programmers.

29 codes that point to a layer

Names and numbers are Chromium’s. The explanations are ours: what the code means in plain words and where it points on the layer map. Where a code alone cannot decide between the website and your own network, the text says so and names the comparison check that can.

29 rows
Chrome network errors that point to a layer
CodeNo.What it means and where it pointsNext check
ERR_FILE_NOT_FOUND-6A file on this device was not found – as with an address that starts with file://. No network layer is involved.
ERR_TIMED_OUT-7An operation ran out of time without an answer. For a web page that means the same as a connection timeout: the server or the path to it did not respond. Compare with mobile data to see which side it follows.“This site can’t be reached”
ERR_BLOCKED_BY_CLIENT-20Something inside the browser blocked the request – in practice an extension such as a content blocker. The network and the website are not involved. A private window, where extensions are normally off, shows it at once.one website won’t load
ERR_NETWORK_CHANGED-21The device’s network changed while the page was loading – a switch between Wi-Fi, cable and mobile data, a VPN connecting, or a new address from the router. Reload once. If it keeps coming back, the Wi-Fi link or the VPN is unstable.Wi-Fi connected but no internet
ERR_BLOCKED_BY_ADMINISTRATOR-22A policy set by whoever manages this browser or device blocks the address. On a work or school device that is IT’s decision; on a private device, check whether the browser says it is “managed” and by whom.one website won’t load
ERR_CONNECTION_CLOSED-100The other side closed the connection before sending a page. As with a reset, the server or a device in between ended it; compare with another network and another browser.“This site can’t be reached”
ERR_CONNECTION_RESET-101A connection existed and was cut off. The cut can come from the server or from anything in between that inspects traffic – security software, a company or hotel filter, a VPN. If the site opens on mobile data, look at your own network and device.“This site can’t be reached”
ERR_CONNECTION_REFUSED-102Something at that address answered and actively refused the connection. That is different from a timeout: the path works. It fits a server whose web service is not running, an address with a wrong port, or a firewall that rejects instead of ignoring.“This site can’t be reached”
ERR_CONNECTION_ABORTED-103The connection was given up because the other side did not confirm data in time. It points to an unstable path – weak Wi-Fi, a struggling router or a server in trouble – rather than to a wrong setting.“This site can’t be reached”
ERR_CONNECTION_FAILED-104The connection attempt failed without a more specific reason. On its own it does not name a layer; the comparison checks (other sites, mobile data, another browser) have to.“This site can’t be reached”
ERR_NAME_NOT_RESOLVED-105The name lookup (DNS) failed, so no connection to the website was even attempted. Either the address is misspelled or no longer exists, or the DNS server your network uses gave no usable answer. If other sites open, check the spelling first, then test the DNS server.“This site can’t be reached”
ERR_INTERNET_DISCONNECTED-106Chrome sees no network connection on this device. The website, your provider and the internet at large were never asked – the cause sits between this device and the router.Wi-Fi connected but no internet
ERR_SSL_PROTOCOL_ERROR-107Browser and server could not set up the encrypted connection. Do not look for a way round it. Test another device and another network to see whether it follows the website or your side – security software that inspects encrypted traffic can cause it.one website won’t load
ERR_ADDRESS_UNREACHABLE-109The device knows the server’s address but has no route to it. That is a network-level fault: the router, the provider or a VPN – not the browser and usually not the website.Wi-Fi connected but no internet
ERR_TUNNEL_CONNECTION_FAILED-111A connection through a proxy could not be set up. As with other proxy errors, the place to look is the proxy or VPN configured on this device or network.Wi-Fi connected but no internet
ERR_SSL_VERSION_OR_CIPHER_MISMATCH-113Browser and server have no encryption method in common. That is decided by the server’s configuration or by software that inspects encrypted traffic; nothing on a normal home device needs changing.one website won’t load
ERR_CONNECTION_TIMED_OUT-118The name was found, a connection was tried and nobody answered in time. DNS is not the problem. Either the server is down or overloaded, or something on the way silently drops the traffic – a firewall, a VPN or a filter. The comparison with mobile data separates the two.“This site can’t be reached”
ERR_PROXY_CONNECTION_FAILED-130The browser is set to use a proxy server and could not reach it. The website never saw the request. Check the proxy setting of the system or of a VPN or security app that installed one.Wi-Fi connected but no internet
ERR_NETWORK_ACCESS_DENIED-138The browser was not allowed to use the network. Chromium’s own note says this is most likely a firewall – look at the firewall or security software on this device, not at the router.one website won’t load
ERR_CERT_DATE_INVALID-201By your device’s clock the site’s certificate is expired or not yet valid. Chromium lists three possible reasons: an attacker with an old certificate, a misconfigured server – or a wrong clock on your device. Check date, time and time zone first; do not click through.one website won’t load
ERR_INVALID_URL-300The address itself is not a valid URL. Check for a typing mistake, a stray space or a missing part.
ERR_TOO_MANY_REDIRECTS-310The site sent the browser from address to address in a circle. Either the website is misconfigured or a cookie it stored in your browser no longer fits. A private window tells the two apart.one website won’t load
ERR_UNSAFE_PORT-312The address contains a port number that Chrome refuses to connect to for web pages. That is the browser’s own safety rule, not a network fault.Port reference
ERR_EMPTY_RESPONSE-324The server accepted the connection and closed it without sending anything. That is the server’s or an in-between filter’s doing, not a setting in your browser.one website won’t load
ERR_HTTP2_PROTOCOL_ERROR-337An error inside the HTTP/2 conversation with the server. Usually the website’s side or a device in between; test another network and another browser before changing anything.one website won’t load
ERR_QUIC_PROTOCOL_ERROR-356An error in QUIC, the transport Chrome uses for HTTP/3. Usually the website’s side or a network that handles QUIC badly; test another network and another browser.one website won’t load
ERR_HTTP_RESPONSE_CODE_FAILURE-379The server answered, but with an HTTP error status. The connection and DNS are fine; the status code (404, 500, 503 …) says more.HTTP status codes
ERR_DNS_TIMED_OUT-803The DNS server did not answer in time. The website was never contacted; the fault is between this device and the DNS server – router, provider or a DNS setting on the device.DNS server not responding
ERR_DNS_SERVER_FAILURE-817The DNS server answered with a failure. The website was never contacted; test another DNS server to see whether your network’s DNS is the problem.DNS server not responding

The DNS_PROBE codes

When a name lookup fails, Chrome runs a short DNS test of its own and replaces the code on the page with the result. These 8 statuses are defined in a second source file; while the test runs, the page can briefly show one of the “not finished” statuses.

8 rows
Chrome DNS probe statuses
Code on the error pageWhat it means and where it pointsNext check
DNS_PROBE_POSSIBLEChrome has not run its DNS test yet; the code on the page changes when it has.“This site can’t be reached”
DNS_PROBE_NOT_RUNChrome did not run its DNS test, so the code says nothing about the cause.“This site can’t be reached”
DNS_PROBE_STARTEDChrome is still testing DNS; the code on the page changes when the test has finished. Wait a few seconds.“This site can’t be reached”
DNS_PROBE_FINISHED_INCONCLUSIVEChrome’s DNS test reached no conclusion. Use the comparison checks instead.“This site can’t be reached”
DNS_PROBE_FINISHED_NO_INTERNETChrome’s DNS test found no internet connection at all. Start with the connection, not with the website.Wi-Fi connected but no internet
DNS_PROBE_FINISHED_BAD_CONFIGChrome’s DNS test says the DNS settings are wrong or the DNS servers are down. Look for a manual DNS entry or a VPN on this device, then at the router.DNS server not responding
DNS_PROBE_FINISHED_NXDOMAINChrome ran its own DNS test: the DNS servers work, so the name does not exist. Check the spelling of the address. If it is right, the site’s domain may have lapsed – or a filter on your network answers “no such name” on purpose.“This site can’t be reached”
DNS_PROBE_FINISHED_BAD_SECURE_CONFIGChrome’s DNS test failed with the secure DNS (DNS over HTTPS) provider set in Chrome. The network’s normal DNS may be fine – check Chrome’s secure DNS setting.DNS server not responding

Sources and how this page was made

Only the code names, their numbers and the range boundaries were taken from the two Chromium source files below, as they stood on the main branch on the retrieval date. Chromium’s comments on the codes are not reproduced here. Every explanation on this page was written by ClickSolve Guide from the meaning of the code; the errors were not provoked one by one on test devices.
