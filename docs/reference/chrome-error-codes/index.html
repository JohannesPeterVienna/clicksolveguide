Chrome network error codes (ERR_…)

The small grey code on a Chrome error page – ERR_NAME_NOT_RESOLVED, ERR_CONNECTION_RESET – comes from one list in Chromium’s source code. This page shows that complete list, 249 codes with Chromium’s own one-line description, and adds for the 29 codes people actually meet which layer each one points to and which check comes next.

How to read a Chrome code

Chromium, the open-source project behind Chrome, Edge, Brave, Opera and Vivaldi, numbers its network errors in ranges. The range already says a lot: codes from -100 to -199 are connection errors, -200 to -299 certificate errors, -300 to -399 HTTP errors, -800 to -899 errors of the built-in DNS client. The name shown on the error page is the list’s name with “ERR_” in front; the number appears on some pages and in logs.

Chromium’s descriptions are written for programmers and say what happened inside the browser, not what to do. The column “What it tells you” is this site’s reading for the codes where one layer is clearly indicated; where a code alone cannot decide between the website and your own network, it says so and names the comparison check that can. Codes without an entry in that column get the note for their range.

The DNS_PROBE codes are a separate list

When a name lookup fails, Chrome runs its own short DNS test and replaces the code on the page with the result. These statuses are defined in a different source file, and Chromium’s comment says the status name is what is “presented to the user as part of the DNS error page”.
