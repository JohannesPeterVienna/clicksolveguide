“This site can’t be reached” in Chrome: what it means and what to check

Chrome shows the same grey error page for very different problems. The small code under the headline tells them apart. Pick the code in the diagnosis and it will lead you to the layer that failed – from a typo in the address to a block on your network.

    What the message really says
    


    “This site can’t be reached” means Chrome tried to open a connection to the address and gave up before the website sent anything back. It doesn’t say why. The reason is in the code printed underneath in capital letters – on a phone you may have to tap “Details” first. These codes come straight from Chrome’s networking code, and each one marks the point where the connection stopped.
    

    Opening a website takes four steps: Chrome needs a working network, then a DNS server translates the name (example.com) into a number, then Chrome connects to that number, and finally the server answers. A code tells you which step failed – and therefore which layers you can stop worrying about. A timeout, for instance, means the name lookup already worked; there is no point in changing DNS servers for it.

    The table is a starting point, not a verdict. A timeout can come from a site that is down, but also from a firewall on your network that silently drops connections to it. That is why the diagnosis compares your connection with mobile data before it blames either side.
    

    Why DNS errors are the most common
    


    DNS – the Domain Name System – is the internet’s address book. Your router usually passes on the DNS servers of your internet provider, and every device in the home asks those servers whenever it opens a name. If they are slow, overloaded or filtered, Chrome reports a name error even though the website and your connection are fine.
    

    NXDOMAIN is a specific answer: the DNS server replied “there is no such name”. That is normal for typos and for domains that have expired. It becomes suspicious when the same address works on mobile data, because then your network’s DNS server is giving a different answer than the rest of the internet – sometimes because of a fault, sometimes because a parental control or a company filter blocks the name on purpose.
    

    Chrome adds one more layer of its own: the “Use secure DNS” setting. When it is on with a custom provider, Chrome sends lookups to that provider directly instead of using your system’s DNS. If that provider is blocked on your network, every lookup in Chrome fails while Edge or Safari on the same device work. The diagnosis checks this by comparing browsers.

    Typos and lookalike addresses
    


    A surprising share of NXDOMAIN errors are simple misspellings – a missing letter, a swapped pair, “.co” instead of “.com”. Retyping fixes them. The bigger risk lies in the other direction: an address that is almost right and does load. Scammers register lookalike domains for banks, shops and software vendors precisely because people mistype them. When you reach a page through a misspelled address, check it before entering anything.
    

    For sites you use regularly, a bookmark is safer than typing or searching. Search ads can lead to lookalike pages too, especially for “support” and “download” searches.
    

    Settings inside Chrome worth checking
    


    When the comparison shows that only Chrome fails, three settings are the usual suspects. Extensions come first: VPN, proxy, ad-blocking and security extensions all sit between Chrome and the network. Open Windows 11Chrome menu (⋮) > Extensions > Manage Extensions and switch them off one at a time.
    

    Second, secure DNS: Windows 11Chrome menu (⋮) > Settings > Privacy and security > Security > Use secure DNS. Note the current setting before you change it. Third, stored data for the site: clearing cached files is harmless, but clearing cookies signs you out, so limit it to the one site.
    

    On a company or school computer some of these settings may be managed by IT and locked. Chrome then shows a note that your browser is managed; in that case the IT department is the right contact.
    

    Two commands that confirm a DNS problem
    


    On a computer you can ask DNS directly, without Chrome. Replace example.com with the address that fails. These commands only read information.
    

    Windows · Command Prompt or Terminal
    

    nslookup example.com
    

    What it does: asks your DNS server for the address of the name. “Non-existent domain” is the NXDOMAIN answer; a timeout means the DNS server didn’t reply.
    What it does not do: contact the website or change any setting.
    

    macOS · Terminal
    

    nslookup example.com
    

    What it does: asks your DNS server for the name’s address and prints the reply.
    What it does not do: change anything on the Mac.
    

    Windows · Command Prompt or Terminal
    

    ipconfig /flushdns
    

    What it does: empties Windows’ cache of recent lookups, so the next visit asks DNS again.
    What it does not do: change DNS servers or delete browser data.
    

    macOS · TerminalAdmin needed
    

    sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
    

    What it does: clears the Mac’s DNS cache; Terminal asks for your login password.
    What it does not do: change settings or delete files.
    

    Phones and tablets have no command line; the diagnosis uses the mobile-data comparison instead.
    

    When the problem isn’t on your side
    


    If the address fails on your Wi-Fi and on mobile data, and other people see the same, the website is down or unreachable – only its operator can fix that. Large services publish status pages; smaller ones may post on their official social accounts. ERR_CONNECTION_REFUSED in particular means a server actively said no, which no setting on your device can change.
    

    Be wary of “is it down?” pages that offer a phone number or a download to “fix” the connection. Nothing needs to be installed to wait out a website outage, and no legitimate site asks you to call a number because another site is unreachable.
    


    Questions people ask
    What does DNS_PROBE_FINISHED_NXDOMAIN mean?
    The DNS server answered that the name does not exist. Usually the address is misspelled or the domain has expired. If the same address works on mobile data, your network’s DNS server or a filter on your network is the cause.
    Why does the site work in Edge but not in Chrome?
    Then the network and the website are fine and something inside Chrome differs: an extension, the “Use secure DNS” setting, a proxy extension or stored site data.
    Is ERR_CONNECTION_REFUSED my fault?
    Rarely. It means a server answered and refused the connection – typically the website is down or not accepting connections. A wrong proxy setting on your device can cause it too, which the browser comparison reveals.
    Should I change my DNS server to fix it?
    Only as a test after the comparison shows a DNS problem on your network, and with a note of the old setting so you can undo it. For timeouts or refused connections, changing DNS doesn’t help.
